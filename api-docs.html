Overview

接入概览

无全局 Authorization 请求头

POST 请求使用 Content-Type: application/json。 卡密、Session、Token、SessionKey 与用户 ID 只通过 JSON 请求体提交。

1 MiB请求体上限
1–50批量卡密数量
60 秒限流统计窗口
不重试激活与换卡异常

单卡激活

先调用 /api/check；若返回 service_product， 原样传给 /api/service_status。最后根据产品要求提交 session_info 或 uid。

批量操作

cdkeys 为 1–50 项字符串数组，并必须提交用户完成验证后获得的 一次性 captcha_token。

Responses

不能只判断 HTTP 200

{
  "success": false,
  "code": "cdk.not_found",
  "msg": "卡密不存在",
  "data": null
}
  • HTTP 200 只表示请求已被处理，仍需检查 JSON 中的 success 与 code。
  • 批量接口最外层成功不代表每张卡成功，必须逐项判断 data.results[*].success。
  • HTTP 422 通常返回 detail[] 参数校验信息；HTTP 429 表示 IP 限流。
  • upstream_error 的空结果不能解释为全部卡密失败。

Safety

安全与重试要求

禁止进入 URL

卡密、Session、Token、SessionKey 和用户 ID 不进入查询参数、日志或统计平台。

保持原始大小写

卡密区分大小写，客户端不得擅自转换或改写中间字符。

不可逆操作确认

换卡成功后旧卡立即失效；必须完整展示并保存新卡。

异常不自动重试

激活或换卡遇到超时、断网、5xx 或结果不确定时，先人工核查。
